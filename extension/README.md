# scareblock 크롬 확장 (02단계)

**탐지는 규칙 기반이다** — `eval/detect.py`를 그대로 옮긴 `detector-rule.js`가 지연 전
소리를 듣고, 점프 스케어를 찾으면 화면이 거기 닿기 전에 가린다(M2). 동작점은 #35 사전
등록값 `surge_of_quiet = 20`이다. 01단계의 가짜 탐지기는 `config.js`의 `DETECTOR: 'fake'`로
남겨 두었다 — M1을 다시 잴 때 10초 주기가 필요하다.

## 설치

1. `chrome://extensions` 접속
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 `extension/` 폴더 선택
4. 유튜브 영상 페이지로 이동 — **홈·검색에서 클릭해 들어가도 된다**

YAMNet · CLIP(별도 문서 추론)까지 쓰려면 로드 **전에** 한 번 `bash extension/fetch-deps.sh`를 돌린다 —
아래 「별도 문서 추론」 · 「CLIP 시각 경로」. 안 돌려도 확장은 지금처럼 돈다(그 둘만 꺼진다).

> 콘텐츠 스크립트는 매치되는 URL로 **문서가 로드될 때만** 주입된다. 유튜브는 SPA라
> 홈에서 영상을 클릭하면 문서 로드가 없으므로, `/watch`로만 매치하면 실사용 진입
> 경로 대부분에서 확장이 아예 붙지 않는다. 그래서 `youtube.com` 전체로 매치하고
> `main.js`의 `boot()`에서 `location.pathname === '/watch'`로 걸러낸다. 진입 경로가
> 어디든 `yt-navigate-finish` 한 자리로 모인다.

영상이 3초 늦게 재생되고, 정적 뒤 소리가 급등하면 블러가 걸린다.
콘솔에 `규칙 탐지 #n onset=… fire=… (지금 …)` 가 찍히고, 실제 블러는
그 3초 뒤에 나타난다. **그 간격이 이 시스템의 존재 이유다.**

## 콘솔

```js
scareblock.stats()          // 계측값 + M1 판정
scareblock.measure(true)    // 렌더 계측 켜기 (기본 꺼짐)
scareblock.renderTiming()   // 렌더 시간 — eval 의 --render-s 용
scareblock.blurNow()        // 지금 장면을 도달 전에 가린다
scareblock.detections()     // 지금까지 낸 탐지 수
scareblock.visual()         // 시각 특징 — 컷 · 밝기 급변 · 모션 (03단계, 기록만)
scareblock.setSurge(5)      // 데모용 동작점 전환 (기본 20 = E1 동작점)
scareblock.infer()          // 별도 문서 추론 — 왕복 시간 · 실패 수 · 오디오 탭 구간 · 콜백 비용
await scareblock.yamnet()   // 1.5초 전부터 패치 하나의 Speech · 상위 5개 클래스 (확인용)
scareblock.siren()          // 사이렌 — 패치 · 사이렌 수 · 왕복 · 창 끝 뒤 지연 · 화면까지 남은 시간
scareblock.clip()           // CLIP — 프레임 수 · 건너뜀 · 늦음 · 왕복 시간 · 최근 점수 · 종류별 트리거
scareblock.settings()      // 지금 걸린 사용자 설정 (설정 화면)
scareblock.stop()           // 원복
```

## 설정 화면 (04단계 개인화)

툴바의 scareblock 아이콘을 누르면 설정이 뜬다(`settings.html` — 팝업 · 옵션 페이지 · 설치 직후 안내 탭이 같은 파일).
**바꾸면 열려 있는 유튜브 탭에 바로 적용된다.** 값은 `chrome.storage.local`의 `settings` 하나이고,
페이지(MAIN world)에는 `chrome.*`가 없어서 중계(`bridge.js`)가 읽어 window 메시지로 넘긴다 — 추론과 같은 길이다.

| 설정 | 기본 | 하는 일 |
|---|---|---|
| 켜기 | 켬 | 끄면 지연 재생까지 모두 떼고 영상이 원래대로 나온다. 다시 켜면 다시 붙는다 |
| 모드 | 가리기 | **경고만**: 가리지 않고 소리도 줄이지 않는다. 화면에 닿기 1.5초 전부터 위쪽에 「⚠ 곧 …」을 띄운다(`WARN_LEAD_S`) — 지연 버퍼 덕에 미리 안다 |
| 민감도 1~5 | **3 = surge 20 = E1 동작점** | 1 → 60 · 2 → 35 · 4 → 10 · 5 → 5(데모 동작점). 높을수록 작은 급등에도 반응한다. 공포 영상 44클립에서 1분에 0.49 · 1.18 · **2.19** · 3.94 · 6.37번(라벨 없는 스윕, `eval/README.md`). 설정 화면이 이 숫자를 같이 보여 준다 |
| 종류별 | 모두 켬 | 점프 스케어 · 피 · 거미 · 주사기. 끈 종류는 재생기가 건너뛴다(`player.disabledCats`). 수동(`blurNow`)은 끌 수 없다. **피 · 거미 · 주사기를 모두 끄면 CLIP을 멈추고**, 하나라도 켜면 다시 붙인다(`SB.clipWanted`) |

- **기본값 = 지금까지의 동작.** 설정을 안 건드리면 E1과 같은 탐지기 · 같은 블러다
- 저장된 값은 믿지 않는다 — `SB.normalizeSettings`가 모르는 키를 버리고 범위 밖 값을 기본값으로 돌린다
- 첫 설치 때 안내 탭을 연다 — 3초 지연, **안정적인 볼륨 끄기**(켜면 점프 스케어를 절반 가까이 놓친다, #52 실기), 설정 위치
- 설정이 오기 전(최대 0.5초)에는 붙이지 않는다 — 꺼 둔 사용자에게 지연 재생이 잠깐 붙었다 떨어지지 않게
- **E5 실험 빌드(`e394a1d`)에는 없다.** 실험은 설정 화면 없이 고정된 값으로 돈다

```js
scareblock.settings()   // 지금 걸린 설정
```

```bash
node extension/test/settings.test.js   # 11/11 — 값 정리, 민감도 → surge, 재생기 · 탐지기에 걸기, 끈 종류 건너뛰기, 경고 미리 보기가 커서를 안 옮김, 중계 전달
```

**아직 Chrome에서 확인하지 않았다.** 설정 화면 동작은 미리 보기(가짜 저장소)로만, 페이지 적용은 테스트로만 봤다.

## 동작점과 데모 (`setSurge`)

기본 동작점은 **E1과 같은 `surge_of_quiet = 20`** 이다 — 직전 1초 중앙값보다 20배 넘게 커져야 울린다.
이 값은 #35에서 라벨을 보기 전에 정했고 E1 보고값이라 바꾸지 않는다.

**바탕 소리가 깔린 영상에서는 20배에 닿지 않는다.** 2026.10.07, 프레디의 피자가게 데스신 모음
(`qMHZj5zxX0A`, 108초, 사용자가 센 점프 스케어 8개)에서 탐지가 0건이었다. 탐지기가 듣는 RMS를
10 ms마다 기록해 보니 영상 전체에서 가장 큰 급등이 **×8.5**였다. 사람 귀에는 조용해도 환풍기·배경음이
깔려 직전 1초 중앙값이 0.02–0.05에 머물고, 「쾅」이 커도 배율은 3–8배에 그친다.
같은 기록으로 다시 계산하면 ×10·×15에서도 0건, **×5에서 4건**(21.7 · 35.7 · 57.6 · 79.7초)이다.

그래서 데모에서는 동작점을 콘솔에서 바꿔 **두 값을 나란히 보여준다.**

```js
scareblock.setSurge(5)    // 더 잡는다 — 대신 일반 장면에서도 9초에 한 번 울린다 (44클립 스윕 6.37건/분)
scareblock.setSurge(20)   // E1 동작점으로 되돌린다 — 27초에 한 번 (2.19건/분)
```

**5는 E1에 숫자가 있다.** 사전 등록한 민감도 부록(5 · 20 · 35 · 60)의 한 값이라, 데모에서 5를 써도
E1 밖의 값이 아니다(개발 B 확인, 10.07). 5일 때 **recall 66% · 공포 영상 6.1건/분 · 일반 영상 6.9건/분**.
그래서 데모에서 밝힐 것은 「**E1 보고값은 20, 데모는 5**」 한 줄이다.

**프레디 영상만의 일이 아니다.** E1에서 동작점 20이 잡은 27건은 급등 배수 중앙값 **40배**, 놓친 49건은
**6.5배**이고 놓친 49건 중 48건이 20배 미만이다. 배경음 때문에 20배에 못 닿는 것이 놓침의 거의 전부다.

「낮추면 잡지만 오탐이 는다」가 보여줄 내용이다. 오탐을 줄이는 다음 단계가 10.03 말소리 기각
(#35, 일반 영상 오탐 −63%)이다. **데모에서 5를 쓸 때는 E1과 다른 값이라고 밝힌다.**

## 시각 특징 (03단계 착수)

`visual.js`가 **지연 전** 프레임을 2fps로 64×36 휘도로 줄여 세 특징을 낸다.
README 「모델이 아닌 것」의 정의 그대로다 — CLIP과 같은 1~2fps 샘플링 전제.

| 특징 | 계산 | 플래그 |
|---|---|---|
| `hist` | 16구간 휘도 히스토그램의 반 L1 차이 (0~1) | `≥ 0.40` → 컷 |
| `dMean` | 평균 휘도 변화 (−1~1) | `\|dMean\| ≥ 0.30` → 밝기 급변 |
| `motion` | 전역 밝기 이동을 뺀 픽셀 차이 평균 (0~1) | — |

**트리거를 내지 않는다.** 오디오·영상 융합은 향후 과제이고 E1은 오디오 규칙만 잰다.
특징은 기록만 하고 `scareblock.visual()`로 연다. 컷·밝기 급변은 콘솔에 한 줄씩 찍힌다.
**두 임계값은 라벨 없이 발화율로 골랐다(#35, 11.04).** 오디오 동작점과 같이 고르는 규칙을 #35에 먼저 등록하고,
개발용 절반(공포 21클립 · 일반 영상 12클립)에서만 스윕했다. 정답 사건 위치를 보고 고르면 나중에 융합 E1이 그 라벨에 맞춰진 숫자가 된다.

- **밝기 급변 `0.30`** — 규칙은 「일반 영상 1분당 0.5회 이하가 되는 가장 작은 값」인데 격자(0.05–0.30) 안에서 나오지 않아
  등록대로 격자 끝 0.30. 이때도 일반 영상 1.05회/분 · 공포 0.31회/분
- **컷 `0.40` 그대로** — 컷은 편집으로 늘 있어 적게 울리는 값으로 고를 수 없다. 공포 3.6회/분 · 일반 8.1회/분
- 두 특징 모두 **일반 영상에서 공포 영상보다 2~3배 더 울린다** — 혼자서는 무서운 장면 신호가 아니고, 혼자 트리거를 내지 않는 융합용으로 둔 것과 맞다
- 스윕은 ffmpeg로 줄인 프레임이다. Chrome 캔버스 출력과의 대조는 아직이다(줄이는 방식을 바꿔도 1분당 0.15회 안)

재생기와 **따로** rVFC를 건다. 재생기의 `_onFrame`은 M1 계측 경로라 건드리지 않는다.
`motion`에서 전역 밝기 이동을 빼는 것은 페이드·플래시를 모션으로 세지 않기 위해서다.
샘플 간격이 2.5주기를 넘거나 시각이 뒤로 가면(탭 숨김·시크) 그 샘플의 차이 특징은 `null`이다.
샘플이 실패하면(다른 출처 프레임으로 캔버스가 오염돼 `getImageData`가 던지는 경우 등) 캔버스를 새로 만들고
루프는 이어 간다. 5회 연속 실패하면 끄고 콘솔에 남긴다. 실패 수는 `scareblock.visual()`의 `실패`에 센다.

```bash
node extension/test/visual.test.js   # 11/11 — 장면 교체는 컷, 페이드는 모션 아님, 패닝은 컷 아님, 샘플 실패에도 루프 유지
```

**아직 재지 않은 것** — 실제 유튜브에서의 샘플 비용(`샘플비용_ms`)과 M1 영향.
`getImageData`가 동기 되읽기라 2fps에서도 확인이 필요하다.

## 별도 문서 추론 (04단계)

YAMNet(사이렌 · 말소리 기각 #40)을 브라우저에서 돌리기 위한 구조다. **이 단계는 길만 놓는다 —
탐지 동작은 바꾸지 않는다.** 말소리 기각 규칙(θ = 0.1, #35 10.03)은 이 위에 개발 B가 붙인다.

왜 따로 띄우나 — 확장 스크립트는 `<video>`와 오디오 그래프를 직접 잡아야 해서 **유튜브 페이지 안(MAIN world)** 에서 돈다.
그래서 페이지 CSP를 그대로 받아 wasm을 올릴 수 없고 `chrome.*`도 없다. 추론은 확장 출처의 offscreen 문서에서 한다.

```
페이지(MAIN)                     중계(ISOLATED)          서비스 워커             offscreen 문서
audio-tap ─16 kHz 패치─▶ infer-client ─window 메시지─▶ bridge ─ensure─▶ background ─create─▶ offscreen.js
                                         ◀── 점수 521개 ── bridge ◀──── chrome.runtime 메시지 ────  (onnxruntime-web)
```

- **패치는 미디어 시각으로 자른다.** 오디오 탭은 규칙 탐지기와 같은 자리(지연 전 소스)에 물리고, 같은 원점 규칙
  (첫 콜백 `currentTime` + 표본 수, 시크 · 배속 · 버퍼링 복귀에서 리셋)을 쓴다. 리샘플러는 필터 지연을 싣지 않아
  출력 표본 k가 정확히 입력 시각 k/16000초다 — 탐지 onset부터 0.975초를 자르면 eval의 `speech_gate.gate()`(#40 브랜치 `adb83cf`)와 같은 구간이다
- **배속이면** 패치는 들리는 소리 0.975초다(미디어로는 0.975 × 배속초)
- **실패는 null이다.** 모델이 없거나, offscreen이 안 뜨거나, 패치가 고리에서 밀려났거나, 기다리는 사이 시크했으면 null.
  부르는 쪽은 null을 「검증 못 함 → 기각하지 않는다」로 처리한다(#40 클립 끝 처리와 같은 이유)
- **모델이 없으면 비용 0.** 페이지는 offscreen에 상태를 먼저 묻고, `ready`일 때만 오디오 탭을 붙인다

말소리 기각이 부를 것은 하나다:

```js
const s = await SB.yamnet?.scoresAt(onset);   // Float32Array(521) 또는 null
s && s[0]                                     // Speech (AudioSet 클래스 0)
```

**준비** — 런타임과 모델은 저장소에 없다(`.gitignore`). MV3는 원격 코드를 못 불러오므로 확장 안에 둔다.

```bash
bash extension/fetch-deps.sh   # vendor/ ← onnxruntime-web 1.20.1 (npm) · models/ ← _local/models/yamnet/
```

모델은 `docs/yamnet-setup.md`로 만든 `_local/models/yamnet/yamnet.onnx`(eval이 쓰는 것과 같은 파일)를 복사한다.
없으면 스크립트가 그 문서를 가리키고 멈춘다. 파일을 채운 뒤에는 `chrome://extensions`에서 확장을 **새로고침**한다.

```bash
node extension/test/pcm.test.js     # 13/13 — 리샘플이 시각을 밀지 않음 · 8 kHz 위를 접지 않음 · 고리 구간
node extension/test/infer.test.js   # 14/14 — 가짜 chrome · ort로 페이지 → offscreen 왕복(YAMNet · CLIP), 중계는 떨어진 vm, 실패 시 null
node extension/test/speech-gate.test.js   # 10/10 — 말소리 기각: 조건 둘 다 · 20개 클래스 = eval/yamnet.py · 판정 못 하면 그대로 가림
```

**아직 실제 Chrome에서 확인하지 않았다.** 위 테스트는 메시지 모양과 시각 계산까지만 본다. 실기에서 볼 것:

1. `scareblock.infer()`의 `클라이언트.성공`이 늘고 `왕복_ms` 중앙값이 패치 간격(0.48초)보다 충분히 작은지
2. `await scareblock.yamnet()`이 말하는 장면에서 Speech가 높게 나오는지 — 같은 구간을 `eval.yamnet`으로 낸 값과 대조

## E5 실험 진행 도우미 (`tools/e5-session.js`)

사용자 실험(#35 E5)에서 클립 시작 · 끝을 **두 조건에서 같게** 맞춘다. 진행자가 손으로 시크 · 정지하면 조건마다 몇 초씩 달라진다.

- **확장에 기대지 않는다** — 원본 조건은 확장을 끈 프로필에서 보므로 콘솔 스니펫으로 둔다. 확장이 있으면(`window.scareblock`) 필터 조건으로 보고 화면 3초 지연을 계산에 넣는다
- **끝은 절대 시각**이다 — 두 조건 모두 「화면에 보이는 시각」이 `시작점 + 300초`에 닿으면 멈춘다
- **필터 조건은 버퍼를 미리 채운다** — 시작점 1초 앞에서 틀어 화면에 시작 프레임이 보이는 순간 멈춘다. 참가자는 「안전 버퍼 채우는 중…」을 보지 않는다. 이 준비 동안 4초쯤 소리가 난다(아래)
- 준비됨 · 끝 화면은 `#movie_player` 안에 덮어서 유튜브 전체 화면(f)에서도 보인다. 진행 막대 · 제목 줄은 숨긴다
- 진행 중 일시정지 · 시크 · 배속 변경이 끼어들면 기록하고 그 세션을 `유효: false`로 표시한다

```js
// DevTools → Sources → Snippets에 e5로 저장해 두고, 클립 페이지마다 ⌘P → !e5
e5.prepare('c019')   // 준비 — 검은 화면에 「준비됨 — Space 키로 시작」
//  Space            // 시작 → 300초 뒤 「끝」
e5.report()          // 시작 · 끝 보이는 시각, 걸린 초, 끼어든 일, 유효
e5.abort()           // 취소
```

**시작점** — `CLIPS`에 c019(`cBPevvxqmGk` 1164.34초) · c004(`fmwJ4b-h8Bg` 8948.5초)가 들어 있다. `clips-e1.csv`(저장소에 없음)의 `video_id` · `clip_offset`이고, 길이는 등록대로 300초다.
시작 전 확인: 안정적인 볼륨 끔(#52 실기 — 켜면 규칙 탐지가 절반), 광고 없는 계정, 음량, 진행 중 탭 · 창 바꾸지 않기
(숨기면 프레임 콜백이 멈춰 끝 판정이 늦어진다).

- **참가자 중단:** 진행 중 Esc. 유튜브 전체 화면에서는 첫 Esc를 Chrome이 받아 전체 화면만 나가므로 **한 번 더 Esc**, 또는 진행자가 콘솔에 `e5.stop()`
- **필터 준비 중 소리:** 버퍼를 채우는 4초 동안 소리가 나고, 처음 몇 초는 시크 전 위치의 소리(지연선에 남아 있던 것)일 수 있다. 실험은 **노트북 내장 스피커 · 시스템 음량 70%**라(#35 11.23 빌드 고정) 참가자가 앉기 전에 준비하거나, 준비하는 동안만 음소거(F10)했다가 「준비됨」 뒤 풀고 70%를 확인한다

## 렌더 시간 측정 (`--render-s`)

`eval/e1.py`의 적시성 계산은 **탐지 지연 + 렌더링 시간 ≤ lookahead** 로 판정한다.
렌더링 시간이 없으면 p90이 하한으로만 쓰인다. 그 값을 여기서 잰다.

```js
scareblock.measure(true)     // 켜고
// … 1분쯤 재생 …
scareblock.renderTiming()    // 읽는다
```

**기본은 꺼져 있다.** 프레임당 `performance.now()` 2회가 M1 측정에 섞이지 않게 하려는 것이고,
데모 경로에도 계측 비용이 있으면 안 된다. 켤 때 표본을 비우고 새로 모은다.

| 항목 | 뜻 |
|---|---|
| `블러프레임_draw_ms` | 블러를 걸고 그리는 데 걸린 시간 |
| `일반프레임_draw_ms` | 블러 없이 그린 시간 — 차이가 블러 비용이다 |
| `블러프레임_간격_ms` | 블러 프레임의 rAF 간격 — **블러가 비싸면 여기가 늘어난다** |
| `render_s(제안)` | `p90(블러 draw) + 한 프레임 주기` |

**draw 시간은 CPU가 명령을 넣는 시간이라 GPU 완료를 포함하지 않는다.** 그래서 프레임
간격을 함께 본다 — 블러가 GPU에서 비싸면 draw는 짧은데 간격이 늘어난다.

**`render_s(제안)`은 근사다.** 블러 결정은 그 프레임을 그리는 rAF 콜백 안에서 일어나고
픽셀은 다음 합성 시점에 보이므로 `draw + 한 프레임 주기`로 잡았다. 캔버스의 실제 제시
시각은 관측할 수 없다.

측정하려면 **트리거가 실제로 발동해야 한다.** 가짜 탐지기가 10초마다 내므로 1분쯤
재생하면 표본이 쌓인다. 빨리 모으려면 `scareblock.blurNow()`를 몇 번 부른다.

## M1 판정

`stats()`의 `M1통과`는 **`연속무드롭초 ≥ 60`** 일 때 `true`다.

`연속무드롭초`는 마지막 끊김·디코더드롭 이후 흐른 시간이다.
M1 기준이 *"60초 이상 유지"* 이므로 **누적 0이 아니라 연속 60초**가 맞다.
누적으로 재면 오래 돌릴수록 통과가 불가능해진다 — 10분 돌리면 그 안에
한 번만 끊겨도 실패로 잡힌다.

누적값과 `끊김_분당` · `누락_초당` 비율도 함께 낸다. 길이가 다른 측정을
비교하려면 비율이 필요하다.

**`적재누락`은 판정에 넣지 않는다. 사용자가 느끼지 못하는 내부 샘플링 손실**이기
때문이다. (한때 「해상도·캡처율과 무관한 상수라 통제 불가」로 설명했으나 틀렸다 —
프레임마다 부르던 `getVideoPlaybackQuality()`가 원인이었고, 4Hz로 낮추자 초당
18.8에서 0.1로 줄었다.) 근거는 [`poc/README.md`](../poc/README.md).

## CLIP 시각 경로 (04단계 · 피 · 거미 · 주사기)

`eval/clip_zeroshot`(#51)과 피 보강 모델(#53)을 **같은 계산 그대로** 확장에 옮겼다. 정의도 같다 —
1초에 한 장, 프레임 t의 점수가 θ 이상이면 `[t, t+1)`을 가린다.

```
<video>(지연 전) ─rVFC 1fps─▶ 원본 크기 캔버스 ─clipCrop(PIL과 같은 축소 · 자르기)─▶ 224×224 RGB 150 KB
   ─ infer-client ─▶ bridge ─▶ offscreen: clipNormalize → CLIP(onnx) → clipHeads ─▶ {zs, probe} ─▶ clipDecide ─▶ 트리거
```

- **θ는 오프라인에서 정한 그대로다**(config `CLIP_THETA` · `CLIP_PROBE_THETA`, neutral-dev 5%). 바꾸면 #35에 보고한 숫자와 달라진다
  - 리사이즈를 torchvision처럼 **버림**으로 고친 뒤(#51 리뷰 1) 피 보강 모델을 다시 학습해 `CLIP_PROBE_THETA`가 0.05835 → **0.05868**로 바뀌었다.
    zero-shot θ는 그대로다(neutral 클립이 전부 16:9라 점수가 같다). 다시 낸 임베딩 · 점수 · `probe.json`은 `_local/dataset/resize-1123/`
- **피는 보강 모델**이 `models/clip_heads.json`에 있으면 그것을, 없으면 zero-shot을 쓴다. 거미 · 주사기는 zero-shot
- **모델은 eval과 같은 fp32 파일(352 MB)이다.** 줄이면(int8 등) 점수가 달라져 θ가 맞지 않는다. 만드는 법은 [clip-setup](../docs/clip-setup.md)
- **한 번에 한 장만 보낸다.** 앞 장이 안 끝났으면 그 프레임은 건너뛴다(`건너뜀`). 응답이 없으면 가리지 않는다
- **자르기는 확장 프레임에서 한다(11.24).** 처음에는 페이지에서 잘랐는데, 1080p에서 메인 스레드 **66 ms**라 CLIP을 켜면
  1초마다 렌더가 끊겼다(127초에 127번, M1 실패). 유튜브 CSP는 `worker-src`로 blob · data Worker를 둘 다 막는다.
  그래서 숨긴 확장 프레임(`clip-frame.html`)을 넣고, 페이지는 `createImageBitmap`으로 떠서 **옮기기만** 한다(0.3 ms).
  출처가 다른 프레임은 다른 프로세스에서 돌아 페이지를 멈추지 않는다 — 자르는 동안 32 ms 넘는 rAF 간격은 5/300,
  자르지 않을 때 4/228로 같았다. 계산은 같은 `clip-prep.js`라 바이트가 같고, 자른 결과는 프레임이 offscreen에 바로 보낸다
- **비용** (실제 브라우저, onnxruntime-web 1.20.1 wasm 1스레드): 페이지 0.3 ms · 프레임 자르기 약 62 ms(1080p, 다른 프로세스) ·
  추론 약 210 ms/장. `scareblock.clip()`의 `페이지_ms` · `프레임_자르기_ms`로 본다
- **CLIP은 offscreen 안의 전용 Worker(`clip-worker.js`)에서 돈다(11.25).** 예전에는 offscreen 한 스레드 · 한 줄이라 CLIP 한 장(약 210 ms)
  동안 YAMNet이 기다렸다 — CLIP을 켜면 YAMNet 왕복이 26 → 296 ms(#64 실기), 첫 로드(352 MB) 동안은 YAMNet이 아예 멈췄다(#54 리뷰 🟡2).
  이제 **줄도 모델마다 따로**고, 상태 확인(`status` · `clipStatus`)은 줄에 서지 않는다. 계산은 같은 `clip-prep.js` · 같은 모델이라 점수가 같다.
  Worker를 못 띄우면 예전처럼 offscreen 안에서 돈다 — 콘솔 「CLIP 준비 … · 전용 Worker」 / 「offscreen 안」으로 본다

**같은 점수가 나오는지** — 세 겹으로 본다.

```bash
node extension/test/clip-prep.test.js      # 18/18 — 같은 RGB → PIL과 같은 바이트 · 같은 텐서 (16:9 아닌 크기 포함)
node extension/test/clip-sampler.test.js   # 7/7 — 판정 + 저장된 임베딩 → eval 점수와 같다(zero-shot · 보강 모델)
node extension/test/offscreen.test.js      # 6/6 — 모델마다 줄 · CLIP이 도는 동안 YAMNet이 안 기다림 · Worker 점수 = 예전 길 · 못 띄우면 물러남
node extension/test/clip-frame.test.js     # 9/9 — 프레임이 페이지와 같은 바이트로 자름 · 비트맵은 옮김 · 실패는 null · 다른 출처 무시
# 모델 · _local이 없으면 대조를 건너뛰고 「건너뜀」이라고 쓴다 — 그때의 「통과」는 판정 로직만 본 것이다
# 실제 브라우저 wasm: extension/test/clip-browser.html (파일 안 주석대로 띄운다)
#   c018 두 프레임 — eval 점수와 최대 차이 1.3e-5
```

**아직 실제 유튜브 위에서 확인하지 않았다.** 볼 것: `scareblock.clip()`의 `건너뜀` · `늦음`이 0 근처인지,
피 · 거미 장면에서 트리거가 나는지, M1 렌더 지표가 CLIP을 켠 뒤에도 그대로인지.

## 사이렌 (05단계 · #35 11.23 · `eval/siren.py` #62)

**YAMNet 기존 클래스에 임계값만** — 학습 없음. 오디오 탭(지연 전)에서 0.48초마다 패치 하나(0.975초)를 받아
`max(390 Siren, 317 Police car, 318 Ambulance, 319 Fire engine) ≥ θ`면 그 창 `[s, s + 0.975)`를 가린다. 화면에는 3초 뒤에 닿는다.

- **θ = 0.0025** — neutral-dev 가림 5%(#35 결과). 등록 그대로라 config에서 바꾸면 보고한 숫자와 달라진다
- **정의는 eval과 같다** — 패치 k = `x[7680·k : 7680·k + 15600]`(#62 리뷰에서 확인). 격자 기준만 다르다 — 붙일 때 · 다시 맞출 때 `floor((t − 0.975)/0.48)·0.48`(지금 판정할 수 있는 최근 격자), 시크 직후엔 탭 구간 안 첫 격자
- 판정 못 하면(YAMNet 없음 · 패치 못 얻음) 가리지 않는다. 설정에서 「사이렌」을 끄면 샘플러도 멈춘다(0.48초마다 YAMNet을 부르니까)
- **늦을 패치는 건너뛴다** — 결과가 도착할 시각(`max(지금, 창 끝) + 여유`)이 화면에 닿는 시각을 넘을 패치는 버리고, 지금 판정할 수 있는 최근 격자로 다시 맞춘다(#70 리뷰 🟡1). 밀린 패치를 하나씩 따라가면 구간은 빠짐없지만 매번 늦게 가린다. 시크 뒤에는 탭이 들고 있는 구간 안의 첫 격자로 맞춘다. 여유는 최근 64패치 계산 시간 p90을 0.3~1.0초로 자른 값이다(#70 재리뷰 🟢2, `scareblock.siren().여유_s`) — 천장은 다시 맞추자마자 또 건너뛰지 않게
- **기존 사용자도 업데이트하면 사이렌이 켜진다** — 설정에 없는 키는 기본값(켬)으로 채우기 때문이다. 일부러 그렇게 둔다: 평범한 영상에서 가리는 시간이 2% 안팎이고, 끄는 칸이 설정 화면에 있다(#70 리뷰 🟡2)
- 트리거 `confidence`는 1이다 — θ가 0.0025라 점수를 그대로 넣으면 「확신 거의 0」처럼 읽힌다. 점수는 `scareblock.siren().최근`에 있다
- 배속이면 격자가 미디어 시각 기준이라 YAMNet 호출도 실제 시간으로 배속만큼 잦아진다(2배속 → 0.24초마다)

**θ가 아주 낮아 브라우저 쪽 점수 차이에 민감하다**(#62 리뷰 🟡2). 그래서 **브라우저 경로로 다시 쟀다** — 같은 원본 오디오를
48 kHz 스테레오로 풀어 모노 평균 → 확장의 `SB.Resampler`(2048표본씩) → 16 kHz → 같은 YAMNet(onnxruntime).

| | ffmpeg wav (eval, 게시 값) | **브라우저 경로 (JS 리샘플러)** |
|---|---|---|
| neutral-dev 가림 | 4.99% | 4.94% |
| **neutral-test 가림** | 2.13% | **2.06%** (95% 0.9–3.3%) |
| 사이렌 세트 구간 recall | 14/14 | **14/14** · 시간 recall 0.98 |

갈리는 패치는 있지만(혜인 c029: 8/624) **가림 비율 · recall은 같다.** 남은 차이 둘은 실기에서 본다 —
① 실제 유튜브 재생 소리(안정적인 볼륨 끔 기준) ② onnxruntime-web(wasm) vs onnxruntime(Python).

**지연** — eval은 「창 끝 − onset + 0.02 s」(중앙값 0.64 · p90 1.26 s)다. 브라우저는 여기에 탭 콜백 · YAMNet 왕복이 더해진다.
`scareblock.siren()`의 `창끝_뒤_s`가 그 더해진 몫이고, `화면까지_남은_s`가 3초 버퍼에서 남는 시간이다.
사이렌은 0.48초마다 YAMNet을 부르므로 CLIP과 같은 줄에 서면 밀린다 — 줄 나누기 · CLIP 전용 Worker는 #69(혜인)가 한다.

411건은 E1 보고 표의 탐지 수(동작점 20) 그대로다.

브라우저는 48 kHz로 듣고 E1은 16 kHz wav를 썼다. 같은 3클립을 48 kHz로 올려 파이썬끼리
비교하면 52건이 전부 ±50 ms 안에 남고 1건이 더 걸린다 — 표본률 차이는 작다.

**미디어 시각 매핑.** 탐지기는 `ScriptProcessorNode`(2048 샘플)로 듣고, 첫 콜백의
`currentTime`을 원점으로 샘플 수를 센다. 5.000 s · 12.000 s에 급등을 넣은 합성 클립에서
onset이 4.968 s · 11.968 s로 나왔다 — **32 ms 일찍**, 블러가 조금 먼저 걸리는 안전한 쪽이다.
시크·버퍼링 복귀·배속 변경에서는 원점이 깨지므로 탐지기를 처음부터 다시 돌린다.
사용자가 멈췄다 다시 트는 것은 원점이 깨지지 않으므로 이어서 듣는다.

**재생기와 탐지기는 배열 하나로만 만난다.**

```js
[{ time: 13.42, category: "jumpscare", confidence: 0.87, duration: 1.5, source: "rule" }]  // 순간 사건 + 꼬리 1.5초 — 정의는 README 인터페이스 계약
```

`time`은 **라이브 mediaTime**이다. 화면은 그보다 `DELAY_SEC` 뒤를 보여주므로,
표시 시각이 그 구간에 들어올 때 블러가 걸린다.

## 오디오 재동기화

화면은 **mediaTime** 기준으로 `DELAY_SEC` 뒤를 보여주는데 `DelayNode`는 **벽시계**로
지연한다. 정상 재생에서는 둘이 같지만 세 곳에서 어긋난다. 뿌리가 하나라 한 곳에서 받는다.

| 상황 | 그냥 두면 | 처리 |
|---|---|---|
| **일시정지** | 멈춘 뒤에도 소리가 3초 더 난다 | `AudioContext.suspend()` — 지연선 내용이 보존된다 |
| **배속** | 2배속에서 소리가 1.5초 먼저 난다 | `delayTime = DELAY_SEC / rate` — 40 ms 음소거 뒤 교체 |
| **탭 숨김** | 돌아오면 과거 화면이 뜬다 | 링버퍼를 비운다 (시크와 같게) |

**일시정지에서 지연선을 버리면 안 된다.** 그 안에 든 3초는 **화면이 앞으로 보여줄
구간의 소리**다. 아직 한 번도 나간 적이 없다. 버리면 재개 후 3초가 무음이 된다.
그래서 드레인도 폐기도 아닌 **정지**가 답이다.

**배속은 램프로 바꿀 수 없다.** `delayTime`은 지연선의 **길이**라, 늘리면 읽기 지점이
되감겨 소리가 늘어지고 줄이면 건너뛴다(2배속 → 1배속에서 실측). 램프로는 그 점프를
숨길 수 없으므로 40 ms 음소거하고 무음 구간에서 갈아끼운다.

**음소거가 지우는 것은 점프의 클릭이고, 지연선에 든 내용은 아니다.** 배속을 되돌리면
`delayTime`이 1.5 → 3.0으로 뛰지만 지연선 안은 **2배속으로 흘러가던 때 녹음된 구간**
그대로다. 그래서 전환 직후 **이미 들은 말이 한 번 다시 들린다**(실측). 지연선이
1배속 입력으로 다시 차면서 그 뒤는 정상으로 돌아온다.

**고치지 않고 한계로 둔다.** 지연선을 비우면 재개 후 무음이 생기고, 두면 이 재청취가
남는다. 둘 다 대가가 있는데 **배속 전환은 드문 조작**이고 무음이 더 눈에 띈다. 일시정지
쪽 판단과 같은 이유다 — 지연선에 든 소리는 아직 한 번도 나간 적이 없어 버릴 수 없다.

**탭 숨김은 반대다.** rAF·rVFC가 멈춰 링버퍼만 비는데 영상과 오디오는 계속 간다.
돌아왔을 때 버퍼에 남은 건 낡은 프레임뿐이라 그대로 쓰면 과거 화면을 띄운다.
비우고 3초간 검은 화면으로 다시 채운다 — **검은 화면이 가장 안전한 상태**다.

## 설정 변경은 `SB.config` 한 곳으로만 받는다

`world: "MAIN"`이라 `chrome.*`를 못 쓴다. 04단계 설정 UI에는 ISOLATED 콘텐츠
스크립트와 `postMessage` 다리가 필요하다. **그 다리를 04단계에 가서 놓으면 늦다** —
그때는 설정을 읽는 코드가 재생기 안에 흩어진 뒤다.

그래서 규약을 지금 박아둔다. **설정 변경은 `SB.config` 갱신 한 곳으로만 받는다.**
재생기·탐지기는 `SB.config`를 읽을 뿐 어디서 왔는지 묻지 않는다. 다리를 놓을 때
건드릴 자리가 한 곳으로 끝난다.

## 알려진 한계 (01단계에서 남은 것)

- **전체화면·자막·화질설정이 동작하지 않는다** — 캔버스로 다시 그리기 때문
- **광고 미대응** — 광고 중에는 `<video>`가 광고라 링버퍼에 광고 프레임이 쌓인다.
  `#movie_player`의 `ad-showing` 클래스로 감지해 지연을 잠시 끄는 가드를 넣을 수 있다
- **배속을 되돌리면 이미 들은 말이 한 번 다시 들린다** — 지연선 길이만 갈아끼우고
  내용은 남기기 때문. 위 「오디오 재동기화」 참고. 비우는 쪽이 무음을 만들어 더 나쁘다
- 재생 중 화질 자동 전환 시 화면이 한 번 튈 수 있다 (확인 안 됨)
- MV3 `world: "MAIN"`이라 `chrome.*` API를 못 쓴다 (위 「설정 변경」 참고)
- **같은 페이지의 다른 스크립트도 설정 · 추론 메시지를 보낼 수 있다** — 설정(`scareblock-settings` push)과 추론 요청은
  유튜브 페이지 window 메시지로 오가서, 페이지 스크립트가 흉내 내면 그 탭의 설정을 바꿀 수 있다. 저장소(`chrome.storage`)는
  못 바꾸고 그 탭에서만 바뀐다. 오가는 것이 오디오 패치 · 점수 · 설정뿐이라 지금은 두지만, 받는 쪽은 값 검사(`normalizeSettings`)를 한다
