## 0. 요약

유튜브 영상을 3초 늦게 재생하고, 그 3초 동안 위험 장면을 미리 찾아 사용자에게 도달하기 전에
가리는 브라우저 확장을 만든다. 점프 스케어(jump scare)를 첫 구현 대상으로 삼되, 시스템은
**민감 콘텐츠를 "얼마나 미리 알아야 하는가"로 분류하고 각 클래스에 맞는 탐지 경로를 배치하는
프레임워크**로 설계한다.

선행 연구는 이 방향을 여러 차례 가리켰으나 실행하지 않았다. 광과민성 발작 연구는 사용자 도달 전
자극을 완화하지만 저수준 신호(휘도)만 본다. online action detection은 버퍼 안에서 의미론적 사건을
탐지하지만 목적이 정확도이고 개입은 하지 않는다. 상용 트리거 워닝 확장은 픽셀을 보지 않는다.
**이 프로젝트는 각 계열이 남긴 빈칸을 잇는다.**

---

## 1. 문제 정의

점프 스케어는 소리와 화면이 **동시에** 터진다. 재생 중인 화면을 그대로 분석해서는 사용자가 이미 본
뒤에야 판단이 끝난다. 트리거 워닝이 필요한 사람에게 "본 다음의 경고"는 의미가 없다.

기존 대응은 둘 중 하나다.

- **사전 라벨 의존** — 크라우드소싱 타임스탬프. 라벨이 없는 영상에는 무력하다
- **사후 경고** — 이미 노출된 뒤의 알림

둘 다 "노출 자체를 막는다"는 요구를 충족하지 못한다. 노출을 막으려면 **판단이 노출보다 먼저
일어나야 하고**, 그러려면 재생과 분석 사이에 시간차가 있어야 한다.

## 2. 목표와 범위

### 2.1 목표

1. 유튜브 VOD에서 점프 스케어를 자동 탐지해 **사용자 도달 전에** 블러 처리하는 크롬 확장을 구현한다
2. 점프 스케어를 포함한 트리거 카테고리 **5종 이상**(부록 A.2)을 커버하되, 확장 카테고리는
   **파인튜닝 없이** 붙인다
3. 지연 시간과 탐지 성능의 관계를 정량 측정해 **"지연이 필요하다"를 증거로 보인다**

### 2.2 범위 선언

**대상은 유튜브 일반 업로드 VOD로 한정한다.**

영화·대여 등 EME(Widevine)가 걸린 콘텐츠는 **화면 픽셀을 읽을 수 없어** 블러 개입이
불가능하므로 평가셋과 데모에서 제외한다. 이는 구현 미비가 아니라 **브라우저 DRM 규격상의
경계**이며, 서버측 사전처리를 전제하는 별도 아키텍처에서만 다룰 수 있다.

**차단 방식은 실측으로 확인했다**(§6). `drawImage`가 예외를 던지는 cross-origin taint가 아니라
**보호된 프레임이 검은 화면으로 그려진다**. 예외를 잡는 방식으로는 이 경계를 감지할 수 없으므로,
탐지 코드는 픽셀 내용까지 확인해야 한다.

**오디오는 차단되지 않았다.** 따라서 DRM 콘텐츠에서도 오디오 단독 탐지와 경고는 원리적으로
가능하며, 불가능한 것은 화면 개입뿐이다. 이번 범위에서는 다루지 않고 §10에 향후 과제로 남긴다.

### 2.3 비목표

- 실시간 라이브 스트리밍 (VOD로 한정)
- **자체 서버측 영상 처리 파이프라인 구축** (클라이언트 실시간이 주장의 핵심)
  — 외부 API(GPT-4o 등)를 이용한 **오프라인 채점은 상한선 벤치마크**(§7 E2)이지 제품 경로가
  아니므로 이 비목표에 걸리지 않는다. 제품에 통합하지 않는다는 뜻이다
- 콘텐츠 삭제·차단 (가리기와 경고까지. 최종 결정은 사용자)

## 3. 핵심 아이디어

### 3.1 지연 버퍼 — 판단할 시간을 만든다

영상을 3초 미뤄 재생하면 AI가 먼저 읽을 시간이 생긴다. 위험 구간이 발견되면 사용자가 그
장면에 도달하기 전에 블러가 준비된다.

**서버측 사전처리 없이 클라이언트에서 실시간으로 하려면 이 지연이 반드시 필요하다.**
이것이 시스템이 존재하는 이유이자 논문의 첫 주장이다.

**왜 3초인가.** 임의 선택이 아니다. online action detection 연구가 약 2~3초(78프레임) 버퍼에서
THUMOS'14 기준 mAP 13.8%p 향상을 보고했다[1]. 유효성이 보고된 구간을 채택하고,
**11.05 발표에서 축소 평가셋으로 1차 측정한 뒤 05단계에서 전체 평가셋으로 재측정**해
0·0.5·1·2·3·5초 중 우리 과제에서의 최적점을 확인한다.
규칙 탐지기의 실제 판정 지연이 짧을 수 있어 저지연 구간을 촘촘히 잡았고, 3초보다 긴 5초를
남겨 곡선이 평평해지는 지점을 함께 본다 — 그래야 "3초면 충분하다"를 말할 수 있다.

### 3.2 lookahead 요구량 기준 분류 — 이 프로젝트의 설계 주장

민감 콘텐츠를 "무엇인가"가 아니라 **"얼마나 미리 알아야 하는가"** 로 나눈다.
이 축을 모달리티와 교차하면 버퍼가 필요한 칸이 하나뿐이라는 것이 드러난다.

| | 오디오 | 영상 |
|---|---|---|
| **예측 불가형** (버퍼 필요) | **점프 스케어** — 규칙기반 → YAMNet | — |
| **지속 상태형** (버퍼 불필요) | **사이렌** — YAMNet 기존 클래스에 임계값 | **유혈 · 거미 · 주사기** — CLIP zero-shot |

지속 상태형은 화면·소리가 수 초간 유지되므로 프레임 N에서 탐지해 N+1을 가려도 늦지 않다.
**서버측 사전처리 없이 클라이언트에서 실시간으로 개입한다는 전제(§3.1) 아래서, 지연 버퍼가
필요한 것은 예측 불가형뿐이다.** 따라서 **점프 스케어는 카테고리 하나가 아니라 시스템의 제약
조건을 정의하는 대표 클래스**이고, 이 분류가 탐지 경로 배치를 결정한다.

기존 online action detection은 모든 액션에 균일한 버퍼를 적용하며 이런 구분을 두지 않는다[1].

### 3.3 저비용 카테고리 확장

카테고리마다 파인튜닝하는 대신 CLIP zero-shot을 쓴다. 새 카테고리를 **재학습 없이**
추가할 수 있어 확장 비용이 거의 0에 가까워지고, 일정이 밀릴 때 가장 먼저 잘리는 항목이 되지 않는다.

> **단서 — 저비용은 학습 비용이 0이라는 뜻이지 무배포라는 뜻이 아니다.** 새 카테고리 추가는
> 런타임 프롬프트 교체가 아니라 **확장 갱신**을 동반한다(배포 구성은 README 「사용 모델」).

정확도가 부족한 카테고리 1개만 선별해 **보강 모델**로 채운다. 보강 모델의 종류는
실패한 카테고리에 맞춘다 — 거미·주사기처럼 **물체**면 YOLO 파인튜닝이 맞고, 유혈처럼
화면에 퍼진 **색·질감**이면 네모를 칠 대상이 아니므로 경량 이미지 분류기 파인튜닝이 맞다.
어느 카테고리가 부족한지는 **04단계 앞부분**의 카테고리별 정확도 측정에서 나오므로, 도구는 그때 정한다(09.20).

## 4. 관련 연구와 차별점

각 선행 계열이 우리 방향을 **언급했으나 실행하지 않았다.** 참신성 주장을 "우리가 새롭다"가
아니라 **"문헌이 남긴 빈칸을 채운다"** 로 둔다.

| 계열 | 언급한 것 | 하지 않은 것 | 본 연구 |
|---|---|---|---|
| online action detection[1] | 라이브 웹캐스트 NSFW 실시간 red flag | **동기로만 언급, 미구현.** red flag는 알림이지 차단이 아님. 카테고리별 lookahead 구분 없음 | 차단까지 구현, 사용자 실험으로 검증 |
| PSE 연구[2][3] | 사용자 도달 전 자극 완화 | **저수준 신호(휘도 주파수)만.** 버퍼가 시간축 필터링용 | 의미론적 사건을 버퍼 안에서 탐지 |
| affective computing[4][5] | 공포·폭력 구간 탐지 | 목적이 **오프라인 분석·검색** | 재생 중 개입 |
| 트리거 워닝 확장[6] | 트리거 콘텐츠 블러 | **픽셀을 보지 않음** (메타데이터·NLP) | 픽셀·오디오 직접 분석 |

**정리하면**, 버퍼를 쓰는 것도 의미론적 사건을 탐지하는 것도 새롭지 않다. 새로운 것은
**개입을 위해 없던 지연을 의도적으로 도입한 설계 결정**, **lookahead 요구량 기준 분류**,
그리고 **브라우저 클라이언트 실시간 × 다중 카테고리 × zero-shot 확장의 조합**이다.

전체 조사 내역은 [`docs/related-work.md`](related-work.md)에 있다.

## 5. 시스템 설계

```
       유튜브 <video>
            │
    ┌───────┴────────┐
    │                │
 [지연 전]        [지연 경로]
    │                │
    ├─ 오디오 특징    ├─ 영상 링버퍼 (3초)
    ├─ 프레임 샘플링  └─ 오디오 DelayNode (3초)
    │                     │
    ▼                     ▼
  탐지기 ──[트리거 배열]──▶ 재생기 ──▶ 블러 오버레이
                                        + 음량 페이드다운
```

핵심은 **지연 전 신호에서 탐지하고 지연 후 화면에 개입한다**는 것이다. 두 시각 사이의 3초가
개입 예산이다.

**인터페이스 계약** — 탐지기에서 재생기로 넘기는 데이터는 이 배열 하나로 통일한다.

```javascript
[
  { time: 13.42, category: "jumpscare", confidence: 0.87, duration: 1.5, source: "rule" },          // 순간 사건 + 꼬리 1.5초
  { time: 48.10, category: "siren",     confidence: 0.64, duration: 3.5, source: "yamnet" },        // 사이렌 2.0초 + 꼬리 1.5초
  { time: 91.20, category: "blood",     confidence: 0.71, duration: 2.0, source: "clip-zeroshot" }  // 유혈 0.5초 + 꼬리 1.5초
]
```

> **09.10 이후 변경** — `duration`을 **사건이 끝난 뒤 블러가 더 덮는 꼬리 1.5초**로 정의했다. 순간 사건은 `1.5`,
> 지속 사건은 `길이 + 1.5`다. 제출본 예시의 점프 스케어 `1.2`는 꼬리가 라벨 병합 창(1.5초)보다 짧아
> 「라벨 1건 · 개입 두 번」이 되므로 `1.5`로 고쳤다. 정의의 원본은 README 「인터페이스 계약」이다.

`source`에 탐지 주체를 기록해 카테고리별·모델별 성능표 집계에 쓴다.

## 6. 실현 가능성 검증

**착수 전 기술 전제를 실측으로 확인했다** (2026.09.08, Chrome, Big Buck Bunny 60fps).

| 전제 | 결과 | 근거 |
|---|---|---|
| 픽셀 접근 | ✅ | `drawImage(video)` 오류 없음, `toDataURL()` 성공 — **canvas taint 없음** |
| 오디오 접근 | ✅ | `createMediaElementSource` 예외 없음, 지연 전 RMS 25/25 샘플 ≠ 0 |
| 3초 지연 재생 | ✅ | 링버퍼에서 조회한 프레임의 지연 **3.02초** (목표 3.00초) |
| DRM | ⚠️ | 일반 업로드는 접근 가능. EME 콘텐츠(Widevine)는 **픽셀만 차단**(검은 프레임, 비검정 0/58)되고 **오디오는 접근됨**(RMS 0.0675) → §2.2 |

유튜브가 MSE(`blob:` URL)로 미디어를 붙이기 때문에 cross-origin taint가 걸리지 않는다.
프로토타입은 [`poc/delay-playback.js`](../poc/delay-playback.js)에 있으며, 콘솔 스크립트
한 장으로 3초 지연 재생과 오디오 급등 기반 사전 블러가 동작한다.

**즉 이 프로젝트의 기술 전제는 가정이 아니라 확인된 사실이다.** 남은 위험은 "가능한가"가 아니라
"얼마나 매끄럽게 되는가"이며, §9에서 다룬다.

## 7. 실험 계획

| # | 실험 | 무엇을 보이나 | 단계 |
|---|---|---|---|
| **E1** | 지연 시간별 성능 곡선 (0·0.5·1·2·3·5초) | **결과 그 자체.** 사건별 탐지 지연(라벨 onset → 탐지기 확신) 분포의 중앙값·p90·최댓값으로 필요한 lookahead의 양을 측정한다 | **11.05 발표** (09.14 논문에는 설계만) |
| **E3** | 카테고리별 성능 (점프 스케어 vs 지속 상태형) + **유지 시간 T와 필요 lookahead L의 관계** | **"lookahead로 분류해야 한다"의 직접 증거.** 지속 상태형은 지연 0에서도 잡히고 점프 스케어는 못 잡히면 분류가 증명된다. T–L 관계가 나오면 **분류가 목록에서 규칙이 된다** — 새 카테고리는 T만 재서 L을 예측한다 (라벨 `duration` 필요) | 05 |
| E2 | 규칙기반 / 학습모델 / CLIP zero-shot / GPT-4o 4자 비교 | latency-정확도 트레이드오프 | 05 |
| E4 | 720p·1080p 링버퍼 자원 측정 | 브라우저 클라이언트 실행 가능성의 경계 | 01 |
| E5 | 사용자 실험 15~20명 (원본 vs 필터, 놀람 자가보고) | **개입이 실제로 효과가 있는가.** 선행 계열에 없는 유일한 산출 | 05 |
| E6 | XD-Violence로 오디오 규칙 사전 검증 | 라벨링 착수 전 규칙 타당성 확인 | 00~01 |

**E1과 E3가 §3.1·§3.2의 두 주장에 각각 대응한다.** 일정이 밀려도 이 둘은 지킨다.

**E2는 11.05에 넣지 않는다(09.15 변경).** 11.05 발표는 **E1**으로 채운다. E1 라벨링(파일럿 ·
본 라벨링 20클립 · 대조 비율 확인)이 **10.29 전에** 끝났을 때만 YAMNet **사전학습 클래스 점수(학습 없음)**를
탐지 경로 한 열로 더해 규칙 탐지기와 지연·정확도를 비교한다. 3자 비교표는 **05단계(11/30)**로 미루고
GPT-4o 열을 같은 자리에서 붙여 4자를 완성한다 — 오프라인 채점이라 나중에 열을 덧붙여도 표가 깨지지 않는다.
CLIP zero-shot 열이 04단계(확장 카테고리 구현)를 기다려야 하므로 11.19 이전에는 어차피 나오지 않는다.

**미루는 이유는 클립이 없어서가 아니라 라벨링 물량이다(09.20).** 확장 카테고리(유혈·거미·주사기)는
클립을 새로 모아 **멀티카테고리로 라벨링**해야 하고, 그 작업이 점프 스케어 20클립 라벨링과 같은 기간에
겹쳐 11.05 안에 들어가지 않는다(§9 위험 표 「라벨링 물량」). 평가셋 확장은 **원래 03단계에 있었으므로**
「지금 44클립에 없다」만으로는 근거가 되지 않았다 — 확장하면 없어질 사실이기 때문이다. 그래서 확장 자체를
**04단계로 옮겼고**, 옮긴 이유가 **물량**이다.

**표만이 아니라 작업도 미룬다.** 확장 카테고리 수집·라벨링과 CLIP zero-shot 측정은 **04단계**로,
**평가셋 규모 확장(50~80개)**·분류기 학습·**ONNX 변환**과 3자 비교표 작성은 **05단계**로 간다
(규모 확장은 09.21에 04 → 05로 다시 옮겼다 — 아래 물량 참고).
**오디오·영상 융합 비교(early/late fusion)는 향후 과제로 뺀다** — 이 비교가 쓰려던 VGGish·I3D도
같이 쓰는 단계가 없어진다. 04단계는 **앞부분 측정 → 뒷부분 보강 모델**로 순서를 고정해,
「측정 결과를 보고 고른다」가 같은 단계 안에서도 지켜지게 한다. 11.05까지 개발 B는 E1과 조건부 열에만 쓴다.

**옮긴 자리의 물량도 따져야 한다(09.21).** 04단계 앞부분은 **7일**이고, 위험 표는 영상 50~80개
멀티카테고리 라벨링을 **24~39시간**으로 추정한다. 겹침(E1 라벨링과 같은 기간)은 10.22에 풀리지만
절대 물량은 그대로이므로, **규모 확장은 04에서 떼어 05단계로 보냈다** — 그 숫자를 쓰는 곳이
05단계 정량 평가다. **다만 05단계(열흘)도 같은 물량 질문을 받는다.** 이 항목은 03 → 04 → 05로
세 번 옮겨졌고 옮길 곳이 더 없다. 04 앞부분에 남는 것은 **확장 카테고리 클립 수집·멀티카테고리
라벨링과 CLIP 측정**이다.

**그래서 규모 확장에 조건을 단다(09.22).** **05단계에 여유가 있을 때만 확장하고, 없으면 44개
안에서 라벨링한 규모로 고정해 논문에 그 규모를 적는다.** 새 규칙이 아니라 §9 위험 표의
「초과 시 개수 하향」을 이 항목에 적용한 것이다. 아래 「평가셋」 문단의 **「최종 규모는 그대로 둔다」는
09.13에 축소셋을 도입하면서 최종 규모를 함께 줄이지 않는다는 뜻**이었고, 이 조건은 그 최종 규모에
처음으로 단서를 단다 — **목표 80개는 유지하되 05단계 여유에 따라 44개로 고정될 수 있다.**

**이 물량은 E3의 전제이기도 하다.** E3는 점프 스케어와 지속 상태형을 나란히 놓아야 성립하므로,
확장 카테고리 라벨이 언제 생기는지가 곧 E3(05단계)의 선행 조건이다. E3를 지금 옮기지는 않되,
04단계 라벨링이 밀리면 E3부터 흔들린다는 것을 함께 본다.

**평가셋** — 공개 정답지가 전부 영화 기반이라 §2.2 범위 선언과 충돌하므로 **직접 라벨링한
유튜브 VOD**를 쓴다. 영상당 5분 이내 클립 80개(**09.13 기준** — 44개를 먼저 절단해 두었고
11.05 발표용 축소셋 15~20개를 그중에서 라벨링한다. 최종 규모는 그대로 두되 **05단계 여유에 따라
44개로 고정될 수 있다 — 위 물량 참고, 09.22**),
무작위 오프셋으로 절단하고 **점프 스케어가 없는
대조 클립을 30% 이상** 섞는다. 사건 주변만 잘라내면 밀도가 과장돼 precision이 낙관적으로 나오기
때문이다. 공개 데이터셋은 라벨 기준 정의·특징 사전 검증·사전학습에만 쓴다.

### 대외 일정

| 날짜 | 일정 | 대응 산출물 |
|---|---|---|
| 09.10 | 1차 발표 | M0 제안서 + taxonomy |
| **09.14** | **논문 접수 마감** | 설계·실현 가능성 논문 (아래) |
| 10.01 | 2차 발표 | M1 720p 무드롭 3초 지연 |
| 10.29 | 3차 발표 | M2 데모 + 03단계 진행분 |
| **11.05** | **정보처리학회 추계학술대회** | E1 탐지 지연 분포 (+ 조건부 YAMNet 사전학습 열) |
| 11.26 | 4차 발표 | M4 트리거 5종 이상 |

**09.14 논문은 실험 결과 없는 설계·실현 가능성 논문이다.** 쓸 재료는 이미 있다 — §3 설계,
§4 관련 연구, §5 시스템, §6 실현 가능성, §7 실험 **설계**가 그대로 단편 논문 한 편이다.
기여는 **지연 기반 개입이라는 설계 결정과 그 기술 전제의 실측 확인**이다.

> **09.13 이후 변경** — 마감이 **09.16 → 09.14**로 당겨져 **E1 결과를 11.05 발표로 옮긴다.**
> 09.10에 「축소 평가셋으로 E1 표 하나를 만든다」고 정했으나, 이틀이 줄어 본 라벨링이 들어갈 수 없다.
> **라벨링을 서둘러 숫자를 만드는 대신 논문에서 빼기로 했다** — 급히 만든 수치는 나중에
> 되돌릴 수 없고, 이 논문의 기여는 원래 설계와 실현 가능성에 있다.
>
> 09.14 논문에는 **실험 설계**가 들어간다 — 평가셋 구성(클립 44개·212.8분, 씨앗 재현성 확인),
> 라벨 기준, 일치도 절차, 지표 정의. 「측정할 준비를 이만큼 갖췄다」가 그 절의 실질이다.

> **09.15 이후 변경** — **11.05 범위를 E1로 좁힌다.** 확장 카테고리 클립을 새로 모아 멀티카테고리로
> 라벨링하는 물량이 점프 스케어 20클립 라벨링과 겹쳐 11.05 안에 들어가지 않는다(§7). E1 라벨링이
> 10.29 전에 끝나면 학습이 필요 없는 YAMNet 사전학습 클래스 점수만 한 열로 더한다. 확장 카테고리
> 수집·라벨링과 CLIP 측정은 04단계로, 분류기 학습과 3자 비교표는 05단계(11/30)로 간다.
>
> **11.05에서 덜어낸 것은 05단계로 갔다(09.21).** 3자 비교표·GPT-4o 열·분류기 학습·평가셋 규모 확장이
> 05단계 열흘에 얹혔다. 그 단계가 밀리면 §8 「일정이 밀리면 자르는 순서」상
> **사용자 실험(E5)이 먼저 잘리는데**, E5는 §7에서 「선행 계열에 없는 유일한 산출」로 적은 항목이다.
> 그래서 **참가자 모집은 04단계에서 시작**한다 — 05단계에는 실험 진행만 남긴다.
>
> **E1의 마감과 못 끝냈을 때의 대응(09.20).** 좁힌 뒤로 E1이 11.05의 유일한 산출물이라 **라벨이 곧 발표다.**
> **본 라벨링 20클립 완료 목표는 10.22**이고, **10.29 3차 발표를 확인 시점**으로 쓴다 — 그 사이 일주일이
> 밀림을 흡수한다. 10.22를 넘기면 11.05에는 **그때까지 찍은 라벨로 낸 잠정 지연 분포**(사건 건수와
> 「잠정」을 표에 명시)와 **발화율 스윕 표**(라벨 없이 잰 분당 탐지 수, 이미 실측)를 함께 싣는다.
> 빈손으로 가지 않되, 잠정인 것을 숨기지 않는다.

**11.05와 12.10은 각각 M3 마감일·06단계 종료일과 같은 날이라 준비 예산이 0이다.**
학술대회 원고와 최종 발표 자료는 해당 단계 안에서 만들고, 마감 전날 완성을 전제로 하지 않는다.

### 단계

| 단계 | 기간 | 내용 | 마일스톤 |
|---|---|---|---|

> 적재누락은 사용자가 느끼지 못하는 내부 샘플링 손실이라 판정에서 빼고 별도 기록으로 둔다.
> 이 문서의 「720p 무드롭」(위 단계표·대외 일정표, §9 위험 표)은 모두 이 정의로 읽는다.

**02단계가 마지노선이다.** 여기까지 오면 논문이 성립하고 이후는 전부 성능 개선이다.

**역할** — 개발 A(시스템·브라우저)는 9~10월에 부하가 몰리고, 개발 B(모델·데이터·평가)는
9월부터 11월까지 길게 이어진다. 총량이 아니라 시기가 다르다.

**일정이 밀리면 자르는 순서** — ① 헤비 VLM 사전스캔 **통합**(E2의 오프라인 채점은 남는다) ② 개인화 UI ③ 시각 모달리티
④ 사용자 실험. 트리거 카테고리 확장은 CLIP zero-shot으로 비용이 낮아 컷 목록에서 제외한다.

## 10. 기대 결과와 한계

**기대 결과**

1. 유튜브에서 동작하는 크롬 확장 (트리거 5종 이상, 개인 설정)
2. 지연 시간별 성능 곡선 — "지연이 필요하다"의 정량 증거
3. 카테고리별·모델별 성능표 — 규칙기반 / 학습모델 / zero-shot VLM
4. 사용자 실험 결과 — 개입의 실제 효과

**한계**

DRM 콘텐츠에서 화면 개입을 하지 못한다(§2.2). 다만 실측상 오디오는 접근되므로,
**DRM 콘텐츠에 대한 오디오 단독 경고**는 후속 과제로 열려 있다. 캔버스 재렌더로 인한 시청 품질 저하가 남는다.

**오디오·영상 융합 방식 비교(early/late fusion)는 이번 범위에서 빼고 후속 과제로 남긴다(09.20).**
라벨링 물량이 이유이며, 이 비교가 쓰려던 VGGish·I3D도 함께 빠진다(사용 모델 표에서 제거).
이것은 §8 「일정이 밀리면 자르는 순서」에 따른 컷이 **아니라** 범위 변경이다 —
그 목록에 없던 항목이므로, 컷 ①~④보다 먼저 빠진 이유를 여기 남긴다.

경량 zero-shot의 정확도 상한이 명확하므로, 확장 카테고리 성능은 flagship인 점프 스케어에 미치지
못할 것으로 예상한다.

**결과가 기대에 못 미쳐도** 이 연구는 "지연 기반 개입 프레임워크의 적용 한계를 측정했다"로
성립하도록 설계했다. 논문 프레이밍을 결과 독립적으로 유지한다.

## 부록 — 확장 카테고리 taxonomy

M0 산출물. 담당 개발 B.

카테고리를 임의로 고르면 "왜 하필 이 다섯인가"가 심사 질문이 된다. **임상 분류와 상용
트리거 워닝 체계 두 축에 얹어** 선정 근거를 외부에 둔다.

### A.1 선정 기준

| # | 기준 | 이유 |
|---|---|---|
| 1 | **외부 근거가 있는가** | DSM-5 특정공포증 아형[8] 또는 상용 트리거 워닝 체계[9]에 존재하는 항목만 채택 |
| 2 | **지각으로 판별 가능한가** | 픽셀·오디오만으로 판정되어야 한다. 문맥 이해가 필요한 항목은 제외 |
| 3 | **lookahead 클래스가 명확한가** | 예측 불가형 / 지속 상태형으로 나뉘어야 §3.2의 경로 배치가 결정된다 |
| 4 | **2×2의 칸을 채우는가** | 프레임워크가 한 모달리티에 치우치지 않음을 보여야 분류 체계가 작동한다 |

기준 2가 실질적으로 가장 많이 걸러낸다. 상용 체계에는 자살·아동학대·혐오발언처럼
**서사 이해를 요구하는** 항목이 다수인데, 이는 프레임 단위 지각으로 판정할 수 없어
CLIP zero-shot의 범위를 벗어난다. 본 연구는 **지각 기반 트리거**로 범위를 한정한다.

### A.2 카테고리 5종

| # | 카테고리 | lookahead 클래스 | 모달리티 | 탐지 경로 | 외부 근거 |
|---|---|---|---|---|---|
| **C1** | **점프 스케어** | **예측 불가형** | 오디오 (+영상) | 규칙기반 → YAMNet | 상용 체계 Fear Triggers의 명시 항목[9]; 놀람 반사 문헌 |
| **C2** | **유혈** | 지속 상태형 | 영상 | CLIP zero-shot | DSM-5 **혈액-주사-손상형**(BII)[8]; 상용 체계 blood/gore[9] |
| **C3** | **주사기·의료시술** | 지속 상태형 | 영상 | CLIP zero-shot | DSM-5 **혈액-주사-손상형**(BII)[8]; 상용 체계 Medical Triggers의 needles[9] |
| **C4** | **거미·곤충** | 지속 상태형 | 영상 | CLIP zero-shot | DSM-5 **동물형**[8]; 상용 체계 bugs[9] |
| **C5** | **사이렌·경보음** | 지속 상태형 | **오디오** | YAMNet 임계값 | AudioSet 온톨로지 `Siren` 클래스 |

**C2와 C3는 DSM-5에서 하나의 임상 클러스터다.** 혈액-주사-손상형(blood-injection-injury)은
다른 아형과 달리 남녀 유병률이 거의 같고 실신 반응을 동반하는 별개 유형으로 분류된다[8].
따로 고른 두 카테고리가 아니라 **한 아형의 두 표현**이라는 점이 taxonomy의 근거를 강화한다.

**C5는 근거의 성격이 다르다.** 사이렌은 DSM-5 공포증 아형이 아니고 상용 체계의 명시 항목도
아니다. 채택 이유는 **기준 4** — 2×2에서 「오디오 × 지속 상태형」 칸을 채우는 유일한 후보이며,
이 칸이 비면 "지속 상태형 = 영상"으로 오해되어 분류 체계가 lookahead가 아니라 모달리티 기준으로
읽힌다. AudioSet에 클래스가 이미 있어 구현 비용도 약 1일이다. **임상 근거가 아니라 아키텍처
근거로 선택된 카테고리**임을 명시한다.

### A.3 2×2 배치

| | 오디오 | 영상 |
|---|---|---|
| **예측 불가형** (버퍼 필요) | **C1 점프 스케어** | — |
| **지속 상태형** (버퍼 불필요) | **C5 사이렌** | **C2 유혈 · C3 주사기 · C4 거미** |

왼쪽 위 한 칸만 지연 버퍼를 요구한다. 이것이 §3.2 주장의 시각적 근거다.

### A.4 명시적 제외

| 제외 항목 | 이유 |
|---|---|
| **광과민성 발작 유발 자극**(스트로브·플리커) | PSE 전용 도구가 이미 다루는 영역이고[2][3], 저수준 휘도 신호라 본 연구의 「의미론적 사건」 주장과 층위가 다르다. §4의 차별점을 흐린다 |
| **서사 트리거**(자살·학대·혐오발언 등) | 기준 2 위배. 프레임 단위 지각으로 판정 불가 |
| **성적 콘텐츠** | 유튜브 일반 업로드에 드물고, NSFW 분류기가 별도로 성숙한 영역이라 기여가 겹치지 않는다 |
| **동물 죽음·차량 사고 등 사건형** | 서사 이해가 필요하고, 지속 시간이 가변이라 lookahead 클래스 판정이 불안정하다 |

### A.5 확장 절차

새 카테고리 추가는 세 단계로 끝난다. 이것이 §3.3 「저비용 확장」 주장의 구체적 형태다.

1. **lookahead 클래스 판정** — 화면 또는 소리에 유지되는 시간이 버퍼(3초)보다 길면 지속 상태형,
   짧으면 예측 불가형
2. **탐지 경로 배치** — 지속 상태형·영상이면 CLIP 프롬프트 추가, 지속 상태형·오디오면 YAMNet
   클래스 임계값, 예측 불가형이면 전용 규칙·모델이 필요하다
3. **평가셋 라벨 추가** — 기존 클립에 멀티라벨로 태깅 (재수집 불필요)

1단계는 코드 한 줄 수준이고, **2단계는 임베딩 재계산과 확장 갱신을 동반한다**(§3.3 단서).
라벨 비용은 3단계에 있다.

### A.6 CLIP 프롬프트 초안 (C2–C4)

04단계에서 프롬프트 앙상블·임계값 튜닝의 출발점으로 쓴다. zero-shot은 대조군이 필요하므로
중립 프롬프트를 함께 둔다.

```
C2 유혈      "a bloody wound", "blood on a person", "a bloody scene",
             "blood splatter"
C3 주사기    "a syringe", "a hypodermic needle", "a medical injection",
             "a person receiving an injection"
C4 거미·곤충  "a spider", "a close-up of a large spider",
             "an insect crawling", "a hairy spider on a surface"
중립(대조)   "a normal indoor scene", "people talking", "a landscape",
             "a close-up of an object"
```

**예상 실패 모드** — 붉은 조명·케첩·붉은 의상을 C2로 오탐할 가능성이 가장 높다. 위험 표(§9)의
「CLIP zero-shot 정밀도」 행이 지목하는 지점이며, 05단계 실패 사례 분석의 1순위 관찰 대상이다.

### A.7 미확정

- **C5의 세부 범위** — 응급차·경찰차 사이렌만인지, 화재경보·공습경보까지인지. AudioSet
  `Siren` 하위 클래스 구조를 보고 01단계에 확정한다
- **C4의 경계** — 거미만인지 곤충 전반인지. DSM-5 동물형은 넓지만 CLIP 프롬프트는 좁을수록
  정확하므로, **04단계** 프롬프트 설계에서 카테고리별 정확도를 보고 정한다(09.20 이동)
- **C1의 라벨 단위** — 연속된 두 번의 점프 스케어를 1건으로 셀지 2건으로 셀지.
  01단계 라벨 기준 문서에서 확정한다
